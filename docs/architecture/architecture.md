## System at a glance

Current implemented topology:

```text
Browser main thread
├── production Svelte duel application
│   ├── semantic DOM duel field and typed duel store
│   ├── CSS/SVG non-authoritative field feedback
│   └── typed Worker client
├── isolated deck-editor prototype route
└── isolated visual-novel prototype entry
    ↕ structured-clone domain commands/events (duel only)
Dedicated Duel Worker
├── session controller and public-state projector
├── protocol parser/response encoder
├── deterministic preset-deck opponent
├── preloaded card/script maps
└── frozen vendored ocgcore.sync.wasm
    └── Project Ignis CardScripts
```

Target topology is one shell with three lazy-loaded domain roots. Prototype merge is not production integration; ADR-022 governs migration.

## Shared deck-selection screen

The owning decision is [ADR-055](../ADR/055_ADR_shared_deck_select_domain.md). `src/deck-select/` is a fourth source root beside the three domains: one shared presentational library, not a lazy UI domain of its own. It renders the deck tile, the kebab sheet, the rename and delete dialogs, the sectioned decklist panel, and the screen those parts compose into — header, tools, grid, footer, plus the menu-and-dialog state machine over them.

- **Public entry** — `src/deck-select/index.ts`. Cross-domain imports target it and nothing deeper; [`../../tests/unit/domain-boundaries.test.ts`](../../tests/unit/domain-boundaries.test.ts) freezes its exported names and `eslint.config.js` gives the same rule inline while editing.
- **Who imports it** — the shell's free-play duel start (`src/shell/screens/FreePlayMatchSetup.svelte`), the deck editor's library (`src/deck-editor/components/DeckLibrary.svelte`) and the story's pre-battle briefing (`src/story/screens/PreBattleScreen.svelte`). All three mount the same `DeckSelectScreen`.
- **What it never imports** — any sibling domain. It reaches no storage, no repository and no catalog: each host maps its own records into `DeckTileModel`/`DecklistView` and passes callbacks, which is what keeps the screen from making any host eager. Its ESLint zone excludes the battle, shell, deck-editor and story internals, and each of those zones excludes its internals in return.
- **Byte cost** — it stays a lazy chunk shared by the three hosts rather than being pulled into the shell, so it counts inside each host's domain closure in `scripts/lib/domain-chunk-closure.ts`.
- **Element contract** — `src/deck-select/` is inside `CONTRACT_ROOTS`, so every element it renders is `data-cy`-checked like the four domains around it.

Commits: `e07fa3eb` opened the root; the hosts moved onto it in `a36d2300` (free play), `470bc0e6` (library) and `4776fab0` (story). The whole round is `e1d6692..bc79588a`. The screen's validated visual design is [`../deck-selection-screen-design.md`](../deck-selection-screen-design.md).

## System-wide invariants

- `ocgcore` alone decides legality, effects, and duel results.
- Only the dedicated Worker owns WASM, raw protocol data, scripts, and duel handles.
- The main thread receives clone-safe domain messages and immutable state with explicit presentation visibility. Offline hidden identities may remain in memory but must not be plainly rendered, announced, requested as card art, or included in routine diagnostics.
- Svelte owns all interactive application/field UI; presentation state never determines legality.
- CSS/SVG feedback is non-authoritative. Future canvas may be pointer-transparent decoration only after separate measured decision.
- Core callbacks are synchronous and read only preloaded memory.
- Vendored OCG Core is permanently frozen at `vendor/ocgcore-wasm/0.1.2`; no feature updates its binary, loader resolution, or vendor manifest.
- Catalog, scripts, strings, image metadata, and their frozen-core compatibility form one pinned, verified runtime snapshot; browser activation occurs only after runtime and active-image receipts match.
- Production duels shuffle normally; deterministic inputs are restricted to tests and diagnostics.
- Every duel can be reproduced from revision metadata, seed, and ordered responses.
- Headless real-WASM coverage must remain green; production packaging and **Chromium (PWA-capable)** browser gates are required for the release candidate. Firefox/WebKit smoke is optional hygiene, not DOM-field acceptance.

- Update the smallest owning decision file; do not duplicate rules across multiple detail files.
- Update this map when adding, moving, or replacing a decision file.
- A cross-cutting change must update every affected decision in one change.
